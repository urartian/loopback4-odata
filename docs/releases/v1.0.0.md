# v1.0.0 Release Notes

## Summary

`@urartian/loopback4-odata` v1.0.0 establishes the first supported public release of the
package for LoopBack 4 applications. This release focuses on a stable
PostgreSQL-first support contract, stronger production guidance, benchmarked
runtime behavior, generated API reference documentation, and a cleaner release
and governance baseline for future versions.

## Compatibility

- Supported Node version(s): `22.x`
- Supported LoopBack peer range:
  - `@loopback/boot ^8.0.11`
  - `@loopback/core ^7.0.10`
  - `@loopback/repository ^8.0.10`
  - `@loopback/rest ^15.0.11`
- Supported database path: PostgreSQL

## Added

- Standalone user guides for:
  - getting started
  - advanced configuration
  - performance optimization
  - PostgreSQL deployment/setup
  - BI interoperability
  - generic client integration
  - deployment boundaries
  - observability and monitoring
  - cloud deployment guidance
- Generated TypeDoc API reference under `docs/api`
- Release-process, governance, roadmap, security, and community guidance docs
- Manual release-validation benchmark commands for:
  - million-row PostgreSQL dataset validation
  - 100+ concurrent request validation

## Changed

- The documented and supported SQL path for v1 is now PostgreSQL
- Package metadata now includes description, keywords, homepage, repository, and bug tracker links
- Node support is documented and verified against the Node `22.x` baseline
- Release engineering is documented with a lightweight manual publish flow rather than a heavy automation-first model

## Fixed

- Added missing OData operation parameter metadata in shared test fixtures to remove avoidable metadata warnings during boot
- Strengthened release-time documentation consistency across public API, configuration, compatibility, and deployment guidance
- Refreshed dependency baselines to newer compatible LoopBack and tooling patch releases

## Deprecated

- Legacy unsigned paging/delta token support remains available only as a temporary compatibility switch via `allowLegacyUnsignedTokens`
- Legacy top-level pagination caps (`maxTop`, `maxSkip`) remain for compatibility, but the intended config shape is the nested `pagination.*` block

## Removed

- No supported public API removals are part of this release

## Security

- Production runtime dependency audit is clean (`npm audit --omit=dev`)
- Tenant resolution now fails closed when tenant throttling is configured and no tenant can be resolved
- Default OData error shaping no longer exposes backend database internals unless debug behavior is explicitly enabled
- Security, observability, and deployment boundaries are now documented explicitly for host LB4 apps

## Upgrade Notes

- Set `ODATA_TOKEN_SECRET` in production before booting the application
- Treat PostgreSQL as the supported SQL path for v1
- Prefer nested pagination config under `pagination.*` for new configuration
- Use a custom streaming `ODataMediaHandler` for large-file scenarios instead of relying on the bounded default property-backed media path
- If your app uses tenant throttling across multiple replicas, bind a shared throttle store instead of relying on the default in-memory store
