# v1.0.3 Release Notes

## Summary

`@urartian/loopback4-odata` v1.0.3 is a patch release focused on OData query
correctness. It fixes transformed string filter handling, closes several
filter evaluation gaps across entity and navigation reads, and hardens query
parser validation so malformed requests fail clearly instead of being ignored
or partially applied.

## Compatibility

- Supported Node version(s): `22.x`
- Supported LoopBack peer range:
  - `@loopback/boot ^8.0.11`
  - `@loopback/core ^7.0.10`
  - `@loopback/repository ^8.0.10`
  - `@loopback/rest ^15.0.11`
- Supported database path: PostgreSQL

## Added

- Regression coverage for transformed string filter pushdown, entity and
  navigation `$filter` handling, scoped `$expand` filter validation, and OData
  parser hardening.

## Changed

- Scoped `$expand(...;$filter=...)` expressions that require unsupported
  relation post-filter evaluation are now rejected with a clear client error
  instead of being silently ignored.
- OData query parsing now rejects malformed query options more consistently,
  including invalid `$top`, `$skip`, `$orderby`, duplicate scalar query options,
  unterminated `$filter` strings, trailing `$filter` tokens, and malformed
  `in (...)` lists.

## Fixed

- Fixed PostgreSQL pushdown for nested transformed string filters such as
  `contains(tolower(name), 'value')`.
- Fixed transformed string function handling in mixed PostgreSQL filter
  pushdown paths.
- Fixed `$filter` handling for entity-by-id reads.
- Fixed `$filter` handling for singleton navigation reads.
- Fixed navigation collection filtering and paging conversion before relation
  repository reads.
- Fixed unsafe scoped `$expand(...;$filter=...)` behavior where unsupported
  relation filters could be dropped instead of enforced.

## Deprecated

- No deprecations are part of this release.

## Removed

- No supported public API removals are part of this release.

## Security

- Hardened OData query validation to avoid silently accepting malformed or
  ambiguous client query options.

## Upgrade Notes

- Requests using unsupported transformed or post-filter-only expressions inside
  scoped `$expand(...;$filter=...)` now receive a client error. Query the
  relation directly or use repository-supported scoped filters such as
  `$expand=items($filter=name eq 'value')`.
- Malformed query options that were previously ignored or partially applied may
  now return `400 Bad Request`.
