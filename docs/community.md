# Community and Support

This project keeps community process intentionally lightweight for v1.

## Where to ask for help

Use the GitHub repository as the primary collaboration surface:

- **Bug reports**: GitHub Issues
- **Feature requests**: GitHub Issues
- **Contribution guidance**: [CONTRIBUTING.md](/workspace/CONTRIBUTING.md)
- **Code of conduct**: [CODE_OF_CONDUCT.md](/workspace/CODE_OF_CONDUCT.md)

If GitHub Discussions is enabled later, it should be used for open-ended
questions and design discussion. Until then, use issues and link to prior
context when a topic grows beyond a bug report.

## Community updates

For v1, regular project updates should stay simple:

- publish release notes with notable changes
- keep [docs/roadmap.md](/workspace/docs/roadmap.md) current as priorities shift
- update [docs/pre-v1-notes.md](/workspace/docs/pre-v1-notes.md) when the
  supported contract changes

This project does not require Slack, Discord, or a separate forum before the
user community actually exists.
